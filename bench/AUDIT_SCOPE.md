# P19 validation scope

## Source and runtime

The checkout commit is recorded in source-manifest.json. The checkout is never
edited. app-original contains byte-identical copies of the page, README, tests,
shared script/style dependencies and license. app-patched is generated by
make_patch.py, and fix.patch is a unified app-only diff.

The permitted pure-JavaScript route is used: Node VM with offline linkedom DOM.
All complete inline scripts run, including page initialization, load hook,
rendering, bus import, and export mounting. Shared scripts run in source order,
except chart-export-auto.js, which requires browser geometry/canvas. Timers are
inert and storage is isolated in memory. An observer records the first matrix
multiplication's actual design matrix without changing its arguments or return
value. A DOM setter observer records the exact forest markup before linkedom
parses it. The initial default result is captured before either observer.

This establishes statistical execution, generated DOM table strings and SVG
coordinates, and actual JSON/CSV/Markdown/report Blob contents. It does not
establish browser layout, screenshot fidelity, accessibility behavior, native
download UI, chart SVG styling, raster PNG/JPG, PDF, autosave restoration, or
cross-app navigation behavior. These are explicitly unverified, not passes.

## Statistical contract

There is one configuration of the estimator: additive random effects, generalized
DerSimonian-Laird, normal 95% intervals with z=1.959963984540054. There is no
common-effect selector, alternative tau estimator, confidence-level selector,
Knapp-Hartung adjustment, z/p display, standard NMA comparison, or Q-difference
test. The tables show components (effect, SE, CI) and observed nonempty
interventions (effect, CI); exports also contain component/combination SEs, Q,
df and tau2. Q is the common-weight additive residual Q. It is not a
between-design inconsistency or additivity-difference statistic.

Only the entire label `control`, case-insensitive, maps to the empty component
set. Other arms split on `+`, with whitespace around the delimiter removed,
and lowercase component labels. Components are sorted. Each contrast row is
C(A)-C(B). Components that occur in both arms cancel. Observed combinations
are sorted component names joined with `+`; there is no enumeration of unseen
combinations. Combination variance includes component covariances.

Each pasted row is independent: there is no study-ID field. The original page
warns about this. Independent-row numerical checks explicitly test that model;
native-study diagnostic mismatches are reported separately and cannot be
described as multi-arm validation. The patch refuses multi-arm/repeated-study
bus imports, where study identity is available, without adding a covariance
model or new method option. Pasted dependence remains undetectable.

Disconnected treatment networks are estimable when the component design has
full column rank; connected treatment networks can still be unidentifiable.
The rank gate is therefore about components, not graph connectedness.
At least two valid contrast rows are required. There is no statistical row or
component cap. Autosave's field-size limit is a storage limit, not a fit cap.

## Corpus and encodings

The installed data catalogue is enumerated programmatically. Every entry is
recorded in dataset-ledger.csv. The netmeta, metadat, meta, metafor, metabook,
mixmeta and mvmeta datasets are inventoried with installed help and structure.
Other packages' catalogue entries are screened for aggregate intervention
networks. Single treatment-versus-control collections without documented
alternative treatments/components, IPD, diagnostic accuracy, prevalence,
correlations, longitudinal outcomes, and general statistical illustrations
are outside this network corpus.

The P16 network recipes are rerun locally, augmented with metabook networks,
mixmeta/mvmeta smoking, and Landenberger's documented CBT-component indicators.
Package aliases remain distinct candidates. Binary outcomes use OR and RR,
continuous raw arms use MD and SMD, stored effects retain their published scale,
and dietary-fat rates use IRR. These are input constructions, not model choices.
No clinically incompatible endpoints are pooled into a single configuration.
All input values are serialized at 17 significant digits.

Original labels are always tested. Separately named encodings map documented
reference interventions to `control`; no inactive selector is invented.
Explicit combination encodings additionally convert Dong's LABA-ICS and
unambiguous 'and' combination labels to `+`. Exact mappings are in corpus.json.
Alternative/'with or without' treatments remain opaque nodes; no fixed
composition is invented. Landenberger yes/no CBT components are joined by `+`,
using non-recidivism effects versus control. Hamza drug@dose labels preserve
distinct interventions; this does not implement a dose-response analysis.

Full data and whole-study two-arm subsets are separate configurations. Study
identities are retained in corpus rows. Invalid effect/SE rows and documented
construction exclusions are in row-exclusions.json. Lopez repeated identical
treatment arms are excluded without inventing aggregation of change-score
effects. Smoking's artificial reference arms are removed according to its
documented design; its pre-existing continuity corrections are retained.
Su2018 contains split-mouth designs; independent-row results are computational
checks only and are not a validated split-mouth analysis.

## R oracle and tolerances

R uses the requested offline libraries; every completed R log prints .libPaths()
and package versions, with portable placeholders replacing machine paths.
Installed help and source snapshots establish the reference implementation.
The full netmeta/netcomb wrapper was run initially; its saved checkpoint is
wrapper-reference.json. The run was interrupted after retaining completed
cases because standard-NMA design decompositions were expensive and outside
the page's output scope. That incomplete run is not claimed as full coverage.

The complete reference calls installed, unmodified netmeta:::prepare and
netmeta:::nma_additive, the actual statistical engine of netcomb/discomb.
It uses the page-defined C matrix and corresponding contrast design. Common
weights obtain Q and DL tau; random weights obtain component and combination
effects and covariance-derived intervals. wrapper-bridge.json checks this
engine route against every saved completed full-wrapper result, including
native-study diagnostics where available. No R package source is changed.
The same core works for connected and disconnected component-identifiable
networks. Public discomb bridge cases also test automatic C construction.
Native preparation uses original study IDs, netmeta's lexical contrast/sign
normalization, and installed chkmultiarm validation. Incomplete pair sets and
inconsistent effects are recorded as refusals. Native diagnostics are not a
promise of split-mouth support.

Closed-form numerical tolerance is abs(app-reference)/max(1,abs(reference))
<=1e-9. All page estimators are closed form: no iterative tolerance applies.
The specified p tolerance would be 1e-9 absolute, but the page exposes no
p-values. Counts, component/combination membership, matrices, refusals,
displayed strings, and export round trips use exact checks. Every missing or
invalid reference/app result fails evidence checks; there is no success by
omission. Undefined saturated-model tau2 must be null, not zero. Matching
support refusals are not numerical reference passes.
